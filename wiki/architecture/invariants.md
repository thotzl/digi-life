# Invariants (do not regress)

The one copy of the cross-cutting rules (TCK-203). Skills, guides and contracts refer to them by number and do not
restate them; seam-specific rules live in the seam's contract. Every rule is verified against the code; breaking one
has caused real defects before. Numbers are stable: a new rule is appended.

1. **Mode is owned by the router.** The mode changes only through the `set_mode` command (`setMode` in `frontend/core/ipc.ts`), called only by `navigateTo` in `frontend/core/router.ts`; `handle_client_action` rejects a `SET_MODE` action and `send` does not accept one (TCK-157). The trainer view (`frontend/views/trainer/index.ts`) must never set the trainer mode on load (it only resets to `ocean` on `unload`). Otherwise the Ocean is frozen on startup. The backend does not change the mode on its own either: `CLIENT_READY` only answers with `INIT_STATE` (forcing Ocean there switched the trainer off after a fast navigation, TCK-186).
2. **Warp cap of 35 steps per frame.** `MAX_STEPS_PER_FRAME` (`src/server/engine/mode.rs`, TCK-156): `clamp_warp` caps the Ocean warp (`SET_SIMULATION_SPEED`) and the trainer warp (`warpSpeed`) when they are set, and the clamped value is echoed (`SIM_STATE.speed`, `TRAINER_STATE_CHANGED.warpSpeed`). Unbounded steps block the action channel; Pause stops responding. Test `test_warp_is_clamped_and_echoed_for_ocean_and_trainer`.
3. **Reset clears the newborn queue.** `RESET_EVOLUTION` clears `OceanMode::newborns`; otherwise the client re-adds stale creatures. The queue only notifies the UI: every creature in it (mitosis child, restocked or released founder) is already in the simulated population (TCK-143). Test `test_reset_repopulates_from_the_catalogue_and_clears_newborns_and_snapshot`.
4. **Thrust is scaled, never raw.** The motor output `out_thrust` (activation-dependent, typically `tanh` in `[-1, 1]`) goes through `step_creature_kinematics` in `src/shared/physics.rs`, which multiplies it by the thrust that makes full thrust settle at the genome's target speed in `[physics.locomotionSpeedMin, physics.locomotionSpeedMax]` (`target_terminal_speed`, `thrust_for_terminal_speed`, TCK-150). Do not pass raw activation as force. See [[wiki/simulation/physics]].
5. **Bundle icons stay registered.** `tauri.conf.json` → `bundle.icon` must list `icons/icon.ico` and `icons/icon.icns` (valid files, generated via `npx tauri icon`), or the Windows/macOS packagers fail.
6. **No DB work in the hot loop.** Keep SQLite access out of the per-step physics path; batch writes on timers or events (RV-P01). No grid allocation or agent clone per step either; events go through the `EventSink` and leave once per frame. See [[wiki/architecture/simulation-engine]].
7. **Bindings are committed.** After changing a `#[derive(TS)]` struct run `cargo test` and commit `bindings/`; CI fails on drift. See [[wiki/architecture/ipc-protocol]].
8. **Golden master is intentional.** Update `GOLDEN_FINGERPRINT` only for intended phenotype/brain model changes and say so in the ticket. The same holds for the reference reports checked in CI: `tests/reference/trainer-ci.json` (TCK-186), `trainer-ci-curriculum.json` and `trainer-ci-rehearsal.json` (TCK-197) and the Ocean reference `ocean-ci.json` (TCK-158). A behaviour-preserving change (refactor, performance) keeps all of them and the probe JSON identical, including iteration order. The simulation path uses `shared::fmath` for every transcendental function (no std `sin`/`cos`/`exp`/`powf`, TCK-202), so the references are platform-independent. See [[wiki/quality/testing]].
9. **Model change bumps `MODEL_VERSION`.** A change that makes stored genomes' phenotypes or synapse weights invalid (normally one that changes the golden master) bumps `MODEL_VERSION` in `src/persistence/schema.rs` in the same commit; the next start then resets the model tables instead of loading weights that no longer match (TCK-183). See [[wiki/architecture/persistence]].
10. **Dev and installed app never share a data folder.** `npm run tauri:dev` merges `tauri.dev.conf.json`, whose identifier is the release identifier plus `.dev`; the data folder (DB) follows the identifier. A dev build with a new `MODEL_VERSION` would otherwise reset the save data of the installed test version, and two engines would write one DB (TCK-195). See [[wiki/quality/ci-and-tooling]].
11. **`config.json` is the single source of truth for tunables.** No tunable is hardcoded in Rust and no section has a `Default` with values; only the entry points (`src/main.rs`, `src/bin/trainer_runner.rs`) call `AppConfig::global()`, everything else gets the config (or one section) passed in; tests use `config::test_config()` (TCK-138, TCK-198). See [[wiki/contracts/config-section]].
12. **SQL only in `src/persistence/`.** No other module contains SQL or imports `rusqlite`; callers use the repository traits, fire-and-forget failures are logged with `log_db_err`, and no repository result is discarded (TCK-159). See [[wiki/contracts/persistence-repo]].
13. **IPC is typed end to end.** Every message is a ts-rs exported Rust type (`ClientAction`, `UiEvent`, one DTO per command result, `IpcError`): no `json!` payload, no raw-JSON action match, no `serde_json::Value` result. Unknown or malformed actions are rejected and logged at `handle_client_action`. The frontend talks to Tauri only through `frontend/core/ipc.ts` (TCK-157). See [[wiki/contracts/ipc-message]].
14. **The client is a renderer.** Rust owns all simulation state and world data (`INIT_STATE`); the frontend never mutates authoritative state or generates world geometry, it only sends actions. Frontend model types come only from `bindings/` (TCK-115, TCK-160). See [[wiki/contracts/frontend-view]].
15. **Untrusted strings are text.** Names, genomes and log lines go through `textContent` or `escapeHtml` (`frontend/core/escape.ts`), never raw `innerHTML`; `styled` children are text, static markup only through `html()` and never with user or backend data. The CSP in `tauri.conf.json` forbids inline scripts and remote origins (TCK-141, TCK-197).
16. **Simulations are deterministic and IO-free.** `OceanSim`, `TrainerSim`, rooms, evaluators and creature systems do no IO (SQL, Tauri, clock); randomness comes only from seeded `SimRng` streams with named ids (`src/trainer/streams.rs`, the Ocean's `STREAM_*`); creature systems draw no random numbers; parallel and sequential runs give identical results; `parse_genome` is pure and never depends on `HashMap` iteration order (RV-B11, TCK-156, TCK-200).

## Key Takeaways

- Rules 1–3 protect the engine/UI coupling, 4 the physics model, 5 the release build, 6–8 performance and references, 9 stored data across model changes, 10 the save data of an installed test version, 11–13 the seams (config, persistence, IPC), 14–15 the frontend, 16 reproducibility.
- Rules 2 and 3 are covered by the headless engine tests (`server::engine::tests`), 11 by `config::tests`, 13 by the IPC parse and wire-name tests.
