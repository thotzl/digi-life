# TCK-134: Rust Toolchain Baseline and Verification CI

## Description
No pipeline verifies Rust or TypeScript before `release.yml` builds draft installers on every push to `master`. The Windows dev machine had no Rust toolchain.

## Scope
- Install rustup (stable-msvc) locally; record `cargo test` / `cargo clippy` baseline.
- Add `.github/workflows/ci.yml`: `cargo test`, `npm ci && npm run build`, bindings drift check.
- Restrict `release.yml` to `v*` tags and manual dispatch.

## Acceptance
- CI workflow file valid; `cargo test` and `npm run build` green locally.
- No behaviour change in the app.

## Verification
- Local toolchain: rustup stable-msvc, `rustc 1.99.1`, existing MSVC 2017 Build Tools.
- Baseline before any code change (commit `998244e`): `cargo test` 34 passed / 0 failed (3 compiler warnings in `src/bin/cli_trainer.rs`); `cargo clippy --all-targets` 69 lint warnings, 0 errors (clean-up tracked in pool ticket TCK-161).
- `.github/workflows/ci.yml`: push to master / PR / manual: `npm ci`, `npm run build`, `cargo test`, `git diff --exit-code -- bindings/`.
- `.github/workflows/release.yml`: no longer triggered by branch pushes; only `v*` tags and manual dispatch.
- `.gitattributes`: `bindings/**` and `gen/**` forced to LF so generated files do not show as modified on Windows (`core.autocrlf=true`) and the CI drift check is stable.
- `gen/schemas/windows-schema.json` added (generated by tauri-build on Windows, analogous to the tracked linux schema).
